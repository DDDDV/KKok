# 随心唱 · iOS 本地卡拉 OK

基于现有人声分离原型的 iOS 17+ SwiftUI App。导入自己的歌曲，在设备上用
HTDemucs Core ML 分离人声与伴奏，跟随伴奏和歌词录制演唱，再回放或导出自己的表现。

- 三个 Tab 分别管理歌曲库、伴奏库和我的演唱；演唱使用独立的全屏舞台。
- 歌曲库支持批量导入、搜索、按名称/时间排序、待分离筛选、重命名和删除。
  带歌词导入时可选择一首歌曲和一份 `.lrc` / `.elrc`，也可在详情中添加、替换或移除歌词。
- 选歌导入时自动读取内嵌封面和歌词：参考 NetPlayer 的 ID3 APIC/USLT/SYLT/TXXX、
  FLAC PICTURE/Vorbis comment 解析，并使用 AVFoundation 读取 M4A 等系统支持的容器。
  有效时间轴直接用于演唱，纯文本歌词保留供查看并注明无可用时间轴；手动导入的 LRC 优先。
  封面在本机缩为最长边 512 像素的 JPEG，歌曲库、详情和无同步歌词的演唱页使用真实封面。
  旧歌曲首次选中时补读；未发现标签时显示占位封面和“未发现内嵌歌词”。
- 接收当前 iOS 上 Apple 原生框架可读取并解码的音频，不按扩展名拒绝文件。
  包括 MP3、AAC、M4A（AAC 或 ALAC）、WAV、AIFF、CAF、FLAC 等；支持范围最终由
  当前系统的实际解码能力决定。未知扩展名也可选择，损坏、加密或不支持的内容会报错。
- 优先使用 `AVAudioFile`；其他系统可读取的容器使用 `AVAssetReader` 解码第一条音轨。
  均转换为 44.1 kHz 双声道 PCM，再进入同一分离与播放流程。
- 普通 LRC 自动滚动并高亮当前句，增强 LRC 按文件中 `<mm:ss.xx>` 的绝对时间戳
  逐字/词高亮。暂停、续播、前后跳转和拖动进度均读取播放器的同一个时钟。
- 默认播放伴奏，可随时打开“人声”同步听到原唱人声并跟唱；录音时也能开关，伴奏和演唱进度持续。原唱人声仅用于跟唱播放，保存的演唱由麦克风录音与伴奏合成。自动转写始终是可选功能。
- 第一版没有歌词时间偏移调节入口，不进行自动时间对齐。

封面与歌词刮削只读取所选音频文件，不请求网络曲库或扫描未授权的同目录文件。
音频与歌词不上传。导入原曲、封面、歌词、分离结果与转写文本持久保存在 Application Support
的 `VocalSeparator` 目录，切换歌曲或重启不会清理。`library.json` 使用相对文件名记录作品，
避免应用容器路径改变后失效。批量导入先验证全部文件，再原子发布目录清单；失败不会替换旧歌曲。
内部保存的分离结果为 44.1 kHz、双声道 Float32 WAV；导出格式可在设置中选择。
删除分离结果保留原曲；删除歌曲同时删除对应分离结果。两种操作都保留已保存的演唱及成绩。

## 录制、调整、回放与导出演唱

音频导出、分享及转写文字复制／分享需要一次性内购解锁；已购用户可恢复购买，后续无需重复付费。
购买页包含中英文隐私政策与使用条款链接。商品配置、本地 StoreKit 测试和正式商店验收见
[内购接入说明](docs/in-app-purchases.md)。

1. 从伴奏库或歌曲详情点击“进入演唱”，进入全屏舞台后点击麦克风开始录制。
   首次使用会请求麦克风权限；未授权不会创建录音。
2. 伴奏从开头播放，麦克风同步录制。启用评分时，首次演唱会先在本机分析原唱参考旋律并缓存；
   歌词上方显示滚动参考音符、紫色演唱音高轨迹、命中光点、偏高／偏低提示和实时音准分。
   录音期间禁止切换音轨、拖动、普通播放、更换歌曲、再次分离和转写。
3. 点击“结束演唱”，或伴奏播放完毕后自动结束。保存完成后进入回放页，可拖动进度、
   暂停、继续，并按当次保存的歌词查看演唱。
4. 在回放页调节“我的人声音量”（0%～200%），选择原声、浴室、楼道或音乐厅。
   点击“播放试听”后，调节音量或切换音效会实时生效，播放进度连续；暂停时调整不会自动播放。
   满意后点击“保存调整”。音效仅处理麦克风人声。
5. “导出已保存演唱（含伴奏）”按设置的格式分享已保存的混音；“仅导出原始录音”
   按同一格式设置导出未添加音效的麦克风音轨。
   “我的演唱” Tab 可搜索并打开历史演唱，再次调整、保存，或确认后删除某次演唱。
   退出时可选择保存或放弃本次调整；放弃不会影响上次保存的作品。

无线耳机演唱时启用 A2DP 音乐播放通路，优先使用已连接的有线／USB 麦克风，否则使用手机
麦克风收音；请将手机靠近嘴边。不会启用会优先切入通话音质的 HFP 选项，依据
[Apple 的 A2DP 路由说明](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/allowbluetootha2dp)。
舞台显示实际输出设备，录音时提示实际收音设备；右上角可在开始前选择音频输出。
系统报告的延迟用于对齐录音、歌词时钟和评分，节点无有效延迟值时使用会话报告值，不重复累加。
这不是实测设备校准；不同无线耳机仍可能有同步偏差。有线耳机适合更低延迟的练习。
当前不监听／外放麦克风，也没有回声消除；扬声器外放的伴奏可能被麦克风重复录入。

演唱录音采用同一个 `AVAudioEngine` 播放伴奏与原唱，预定在未来 0.3 秒共同启动，
录音时使用 `.playAndRecord`。输入 tap 仅复制原始麦克风数据，独立队列按 hostTime 和
系统报告的输入／输出延迟对齐，写入设备采样率的单声道 Float32 PCM；结束后由
现有 `AudioInputPreparer` 转换到 44.1 kHz 双声道，分块按“处理后人声 × 人声音量 + 0.7 × 伴奏”混音。
默认不添加效果，人声音量为 100%。试听使用 `AVAudioEngine` 同步播放原始人声与伴奏，
直接更新人声增益和 `AVAudioUnitReverb` 参数，伴奏音量保持 0.7；仅保存时离线渲染文件。
试听通过实时限幅防止大音量削波；保存沿用整段峰值归一化，因此高峰值作品的整体响度可能略有差别。
若峰值超过 0.98，对全曲统一衰减后写入 16-bit WAV，避免直接截断峰值导致削波。
导出时长取录音与伴奏的较短者，提前结束不会附加剩余整首伴奏。

演唱位于 Application Support 的 `SingingPerformances/<UUID>`，与歌曲库分开；
保存曲名、日期、当次歌词、混音、调整参数、原始录音和伴奏。每次编辑都从原始素材生成，
不会叠加上次的混响。新混音写入成功后才原子更新清单，保存失败保留旧作品。
旧版本作品若已删除伴奏副本，可继续回放和导出，但无法再次调整。
草稿先持久化伴奏和元数据，保存失败或进程结束后可重试；成功后删除草稿清单与临时文件。
来电、实际输入／输出设备或音频时钟变化、进入后台会结束演唱并
尝试保存已有部分；后台时间不足会保留草稿，回到应用后可重试。不会自动恢复录音。
准备麦克风产生的路由通知和未改变当前通路的设备通知不会结束录音；闲置试听播放器不会关闭录音会话。

自动化测试覆盖音频混合、时长、播放文件一致性、权限和状态保护、通知处理与磁盘恢复；
录音设备在单元测试中使用替身，没有采集运行测试电脑的麦克风。真人演唱、真机麦克风与
伴奏的实际同步误差、耳机路由和完整歌曲听感仍需设备验收，详见 `VALIDATION.md`。

## 音准练习与演唱评分

- 在“设置 → 演唱评分”中启用／关闭音准评分，并选择休闲模式或严格模式。
  默认启用且使用严格模式。关闭后隐藏音准轨道，跳过参考旋律、实时麦克风音高及结束后的
  评分分析；仍能录音、回放、调整音效和导出。设置保存在本机，重启后保留。
- 设置从下一次演唱生效；每次开始录音时固定开关和模式，保存／恢复时不受后续设置变化影响。
  成绩卡显示当次模式，旧成绩按严格模式显示，不重新计算。
- 点击开始演唱后自动准备参考旋律；使用分离得到的原唱人声，无需歌词音符数据、
  语音转写模型、额外模型下载或服务器。分析失败仍可录音，界面明确提示未评分。
- 采用本地单声部 YIN 基频检测：8 kHz 分析、64 ms 窗口、20 ms 步长，
  音频重采样和分析在独立工作队列运行；UI 根据音频时间戳显示音高。
- 使用耳机输出时评分。外放会把伴奏／原唱重新录入麦克风，因此保留录音但不评分。
  无线耳机使用 A2DP 播放和本地麦克风录音，但硬件报告的延迟只是估计，没有真人设备校准结果。
- 按原调比较：严格模式在 25 音分以内满额记分，偏差到 100 音分时该帧为零，
  50 音分以内计为命中；休闲模式对应为 50／200／100 音分，中间区间线性扣分。
  两种模式都将可靠参考区间内的静音／漏唱计零分，低可信参考及间奏不计分。
  不自动折叠八度；有效参考不足 1 秒不显示总分，逐句有效参考不足 0.3 秒显示横线。
- 提前结束只评价本次录下的片段，末尾不足一个完整分析窗口的部分不扣分。
  启用评分时，结束后从原始录音重新分析，保存总分、命中率、演唱覆盖率、模式、规则版本和逐句成绩；
  在作品页展开逐句成绩可跳转回听。分数会在重启、改名和音效编辑后保留。
- 参考旋律跟随音频文件大小、修改时间和算法版本失效重建；每次录音保留独立评分上下文，
  保存中断后的草稿恢复不依赖歌曲是否还存在。旧作品继续回放／编辑，不凭空补发分数。

这是原调音准练习分，不评价音色、歌词正确性或情感。自动提取的参考旋律未经人工校谱，
和声、合唱、强混响、分离残留及很弱的歌声可能影响识别；低可信筛选不能保证选中主唱。
实机真人演唱、不同耳机的同步偏差和复杂歌曲准确率仍需验收。

## 导出格式设置

三个资料库右上角的齿轮打开“设置”，在“导出格式”中选择：

| 格式 | 导出行为 |
| --- | --- |
| WAV（默认） | 内部 PCM WAV 直接复制，保留采样率、声道和浮点／整数精度；其他来源转换为 Float32 PCM WAV |
| MP3 | LAME 4.0 编码，44.1 kHz，双声道 256 kbps／单声道 128 kbps，写入完整的时长与编码延迟信息 |
| AAC（M4A） | Apple 原生编码，44.1 kHz，双声道 256 kbps／单声道 128 kbps |
| ALAC（M4A） | Apple 原生编码，保留采样率；16 位整数来源使用 16 位，其他来源转为 24 位整数后无损压缩 |

选择跨重启保存，适用于歌曲详情、歌曲／伴奏库菜单、我的演唱菜单、演唱回放页和原始录音。
每次点击导出时固定所选格式，在后台按小块转换独立副本，完整回读检查后打开系统分享。
取消／失败清除本次临时文件；完成分享后也清除临时副本。本机原始素材和保存的音效不变。
ALAC 对浮点和更高精度来源存在量化，不宣称与原 Float32 WAV 逐位相同；超出整数范围的
浮点音频会提示选择 WAV，避免静默削波。保存调整后才能导出演唱的最新效果。

MP3 仅新增独立的 LGPL 动态编码库，不引入 FFmpeg。设置保留“关于与许可”，并提供完整
LAME 许可证、对应源码和独立构建说明的离线导出。工程构建会检查源码包是否与库一致。
具体链接方式、替换工具和**正式分发前的义务**见 [MP3 许可说明](docs/mp3-licensing.md)。

## 歌词格式

普通 LRC：支持分钟/秒（可选小数）、多时间标签、乱序行和同时间的原文/译文。
带时间戳的空行用于结束上一句；没有结束标记时，高亮持续到下一句或歌曲结束。

```text
[ti:示例]
[00:01.00]第一句
[00:05.20][00:12.20]重复的副歌
[00:08.00]
```

增强 LRC（尖括号逐字时间戳）：

```text
[00:01.00]<00:01.00>随<00:01.50>心<00:02.00>唱<00:03.00>
[00:05.00]<00:05.00>Hello <00:05.80>world<00:07.00>
```

也支持 LDDC 导出的方括号逐字 LRC：

```text
[00:01.00]随[00:01.50]心[00:02.00]唱[00:03.00]
```

两种格式都按播放器/录音时钟在字词内渐进高亮，支持自动换行、暂停和向前/向后拖动。
时间标记不会作为歌词正文显示。连续空标记保留字词间的停顿；没有句末时间的最后一词
在起始时间高亮，不推测其持续时间。

时间标签是该字/词的起始时间，最后的空标签可以明确结束时间。不会把一个仅有
词级时间戳的词伪造为有独立字时间戳。支持 UTF-8（含 BOM）、UTF-16 BOM、GB18030；
最大 2 MiB，展开后最多 20,000 行、200,000 个字/词标记。文件内已有的 `[offset:毫秒]` 作为文件原始时间语义读取，没有手动调节。
KRC/QRC/TTML 等其他方言未声明支持，需按实际样例适配。

多语言 Whisper 模型 `large-v3-v20240930_626MB` 不再进入 app bundle。分离完成后，
用户可以不使用文字转写；只有用户在确认说明中选择“同意并继续”时，应用才会下载
约 `602 MiB` 的固定版本模型和 tokenizer。下载内容会逐文件校验大小和 SHA-256，
完整通过后才原子安装到 Application Support；后续可离线转写。第一次在某台设备上
使用时仍可能因 Core ML specialization 较慢；每次转写结束后会卸载 Core ML 权重，
避免与下一次人声分离所用的大模型同时驻留内存。

## 快速开始

当前本地交付目录已包含生成好的 Xcode 工程和约 222 MB 的 HTDemucs FP16 模型；从
Git 新克隆的源码不包含该分离模型，需要先按下文运行 `./Scripts/bootstrap.sh`。当前
可推送分支只跟踪小型 `MODEL_MANIFEST.json`，不会推送约 `602 MiB` 的 Whisper 模型树，
也不会把它打入 app。manifest 记录了固定上游版本、27 个文件的长度和 SHA-256；完整
下载来源和 URL 规则见 [`MODEL_PROVENANCE.md`](MODEL_PROVENANCE.md)。

已有 HTDemucs 本地模型时，安装完整 Xcode 后可直接打开：

```sh
open VocalSeparatorPrototype.xcodeproj
```

在 Xcode 中将目标的 `com.example.VocalSeparatorPrototype` 改成属于你开发
团队的唯一 Bundle Identifier，再选择团队和 iPhone 运行。Simulator 可验证
界面、文件处理和测试，但不能代表 iPhone 上的 Core ML GPU 性能。

从 Git 新克隆、删除了 HTDemucs 捆绑模型，或修改 `project.yml` 需要重新生成工程时，
需要 XcodeGen 并运行 `./Scripts/bootstrap.sh`。该脚本只恢复 HTDemucs：它会下载约
144 MB 的 release 压缩包、校验 SHA-256，再生成工程。

如果不想下载 release 模型，也可在
[`dexxdean/htdemucs-coreml`](https://github.com/dexxdean/htdemucs-coreml)
仓库执行 `python convert.py --fp16`，将产物放到：

```text
VocalSeparator/Resources/Models/HTDemucs_CoreML_FP16.mlpackage
```

再运行 `xcodegen generate --spec project.yml`。

## 按需转写模型与下载线路

`TRANSCRIPTION_MODEL_MIRROR_BASE_URLS` 是逗号或分号分隔的 HTTPS 镜像根列表。
每个镜像根必须按 `MODEL_MANIFEST.json` 中的相对路径提供完整文件树。例如，发行构建
可以设置为自有的中国大陆对象存储/CDN 域名；应用会按配置顺序尝试这些镜像，最后才
尝试固定 revision 的 Hugging Face 上游地址。GitHub 不参与终端用户的模型下载。

中国大陆发行不能只依赖 Hugging Face 这一备用线路。应在发布前配置已完成所需备案的
自有域名与大陆 CDN，并在移动、联通、电信网络上验证冷下载。当前仓库没有可代替发行方
持有的 CDN 域名或上传凭据，因此默认开发构建只能使用固定的境外备用源。

模型安装器具有以下边界：

- 浏览、导入和人声分离都不会触发模型请求；只有确认后的转写动作会调用下载器。
- app 内置的清单属于签名应用的一部分，固定模型和 tokenizer revision，并为每个文件
  固定长度及 SHA-256；下载服务器不能单独替换清单。
- 下载先写入同一 Application Support 卷的 staging 目录，校验全部文件后再原子切换；
  未完成目录不会被识别为可用模型，安装目录也会排除 iCloud 备份。
- `WhisperKitConfig.download` 始终为 `false`；模型文件由应用自己的多镜像安装器管理。

## 真实处理链路

1. File Importer 返回 security-scoped URL；应用在授权期间复制歌曲并验证实际解码，歌词在授权期间读取和解析。
2. `AVAudioConverter` 分批解码并重采样到 44.1 kHz、双声道、non-interleaved
   Float32 临时 CAF。
3. 临时 CAF 按 441,000 帧（10 秒）分块；相邻块重叠 44,100 帧（1 秒）。
4. 模型输入 `audio` 为 Float32 `(1,2,441000)`；捆绑 FP16 模型的
   `sources` 实际为 Float16 `(1,4,2,441000)`（FP32 版本为 Float32），顺序是
   vocals / drums / bass / other。运行时会校验并支持这两种输出类型。
5. 应用按 `MLMultiArray.strides` 读输出，只保留人声和三条伴奏 stem 之和。
6. 首尾无衰减、内部互补淡入淡出，滚动 overlap-add 后直接写两个 WAV。
7. 临时 CAF 被删除；失败或取消时不保留半成品目录。成功后将结果写入持久化歌曲库；
   切换歌曲与重启保留所有已导入歌曲及完成的结果。
8. 分离结果先发布并保留，不会自动进入转写。用户明确同意后，应用先确保按需模型已
   安装，再把 `vocals.wav` 交给 WhisperKit。WhisperKit 将输入转为 16 kHz 单声道，
   自动检测语言，并以增量文件模式按 VAD 边界处理长音频；下载、转写失败或取消都不会
   删除已经生成的人声与伴奏。增量回调通过独立的线程安全取消信号停止后续解码，晚到的
   部分结果不会发布到界面。

这种实现不会把整首歌的四个 stem 同时放进内存。Core ML 的一次预测仍不能
保证即时取消，因此点“取消”后会在当前 10 秒推理块结束时停止。

## 已知边界

- 音频解码取决于运行设备的原生解码器；不包含第三方 APE / Vorbis 等解码器。结果导出 WAV。
- 处理需要将应用保持在前台。
- 默认开发构建只带 Hugging Face 备用源；中国大陆正式发行前必须配置并实测自有大陆
  镜像，不能把“存在回退代码”当成网络可用性验收。
- 模型必须用 `.cpuAndGPU`，不能改为 `.all` / Neural Engine。
- 当前 Simulator 的 HTDemucs/Core ML 执行曾产生两份相同的静音 stem，专用集成
  测试已正确拒绝该结果；完整链路必须使用真实 iPhone 验证。
- 已在真实 iPhone 上用用户提供的整首 MP3 跑通分离与中文转写，但歌声识别仍有
  明显错字和少量幻觉文本；本次通过只证明链路和路由正确，不代表歌词级准确率。
- 增量识别会按音频窗口检测语言；界面显示的是各结果中的多数语言，双语歌曲或
  很短的噪声片段可能让语言标签偏离整首歌的主语言，但不影响文本导出。
- 尚未量化峰值内存、温升及多首长音频的准确率与接缝稳定性。
- Whisper 模型与 tokenizer 源文件有意不进入 Git；本地复核副本由 `.gitignore`
  排除。需要重建下载镜像时，应按可信 manifest 从固定上游 revision 获取并重新校验，
  不要把模型载荷或 LFS pointer 加入 app 资源。
- 选取和处理有版权的音乐时，使用者应确保自己拥有相应权利。
